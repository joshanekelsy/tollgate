## Build order

1. Landing hero, qualification form, source capture, and Vercel deployment.
2. Send the live page to qualified users and begin tracking applications.
3. Project record, random route ID, hashed dashboard code, and server-assigned traffic type.
4. Pass-through authorization with explicit no-log/no-store tests.
5. Direct OpenAI real call paid by the caller's key.
6. Usage normalization and provider-scoped price calculation.
7. Project-scoped Convex call record.
8. Protected project dashboard.
9. External product setup.
10. OpenRouter adapter only if steps 1–9 pass.

## Release gates

- Functional: one real external call appears within seconds.
- Security: no prompt, response, header, or key stored; unknown projects and missing authorization never reach the provider; cross-project reads return no data.
- Honesty: estimates are labelled and provider invoice is named as authority.
- Usability: a user can configure it from the README without spoken help.
- Acquisition: a visitor can apply for a test from the landing page and the source is recorded.
