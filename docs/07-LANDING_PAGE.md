# Landing Page Specification

## Job

Move an AI-product operator from one undifferentiated provider bill to a protected customer meter with a clear path to a fixed monthly charge.

## Primary action

`Create a private meter`

## Hero

Headline: `Your customers use AI / Know what to bill.`

Body: meter supported AI usage per customer, close a fixed monthly billing run, and push draft charges to Stripe without storing prompts or responses.

Proof: the same three-customer sample dataset used by `/demo`, showing usage, raw cost, billed amount, margin, unattributed calls, events, customer records, pricing, billing runs, and setup.

Secondary action: `Explore sample dashboard`, linking to the read-only six-view dashboard at `/demo`.

## Argument

1. Customer-level billing outcome.
2. Metering protected by a project write key and retry ID.
3. Attribute, meter, price, and close the month.
4. Fixed billing runs, CSV export, and Stripe draft invoices.
5. Exact provider, privacy, access, and payment boundaries.

## Required limits

Say the exact four fixed non-streaming endpoints. Never imply that every AI model workflow works. State that unknown cost blocks percentage billing unless an exact rate card exists. State that Stripe support creates drafts only and does not send invoices or collect payment. State that recovery-code access is for the private beta.
